## 0. Context warning at 80 % (small, first)

**Now.** Compaction runs at 90 % (`agent/context.py:25` `COMPACT_RATIO = 0.9`, key `cli.compact_ratio`,
`agent/loop.py:318-321`). The estimate counts only conversation messages: `context_tokens()` sums
`message_tokens()` (`context.py:57-59`); `_compact_messages()` passes `self.state.messages` only
(`loop.py:333-342`); `context_usage()` likewise (`loop.py:323-331`). The system prompt (tool descriptions,
skills index, AGENTS.md) and the `tools` JSON schemas sent on every request (`loop.py:356-368`) are not counted,
so real usage is higher than rex thinks. There is no warning to the user.

**Target.** Estimate = system prompt + tool schemas + messages. When the estimate first reaches
`context.warn_percent` (default 80) of the model's window, rex warns once; the flag re-arms after a compaction.
Decision on the optional plain event: **yes**, rex emits `context` after every `final` (one small line, gives the
front-ends a live status line); the warning is the same event with `"warning": true`.

Owner rules (fixed):
- **Auto-compaction at 90 % is mandatory.** It cannot be switched off. `cli.compact_ratio` stays as the key but
  is clamped to 0.5-0.95; 0, negative or missing values fall back to 0.9.
- **Model change recomputes at once.** When the model changes (JSONL `model`/`command model`,
  `jsonl_bridge.py:157-165`; REPL `/model`, `runtime/__main__.py:193`; or a restart with `--model`), rex looks up
  the new window, recomputes the percentage, re-evaluates the warning, and emits `context` right after
  `model_ok`. Example: 200k used on a 220k model = 91 % (would compact) becomes about 18 % on a 1M model: the
  warning clears, the flag re-arms, and nothing is compacted. If the new model is smaller and the percentage is at
  or above 90 %, compaction runs before the next request, as it does today (`loop.py:351-353`). It never runs at
  switch time, so switching back to a larger model loses nothing.
- **Window size per model, in this order:**
  1. config `models.<name>.context_window`. The old keys `agent.context_window` and
     `agent.context_windows` (`context.py:72-80`) still work as overrides.
  2. The endpoint, if it reports the window. The LiteLLM proxy has `GET /model/info` (`max_input_tokens`), and
     some OpenAI-compatible servers put `context_length` in `/v1/models`. rex asks once per model with a 3 s
     timeout and caches the answer for the process. A failure falls through silently.
  3. The built-in table in `llm/models.py` (`max_input_tokens`).
  4. A size hint in the model name (`200k`, `1m`).
  5. A conservative default of **32 000** (today it is 200k, `DEFAULT_CONTEXT_WINDOW`). A small default compacts
     early instead of overflowing.
  The `context` event carries `"source"` (`config`/`endpoint`/`table`/`name`/`default`). When the source is
  `default`, the REPL tells the user once to set `models.<name>.context_window`.

**Design.** `context.py`: new `overhead_tokens(system_prompt, tool_schemas)`; `compact_messages()` gets the
threshold minus overhead. `AgentLoop`: new optional callback `on_context(dict)`; after each turn compute
`{"used","limit","percent","model"}`, call it; when `percent >= warn_percent` and not yet warned, add
`"warning": true` and set `_ctx_warned`; clear `_ctx_warned` when `_compact_messages` changed something or on
`reset_context()`. Bridge emits `{"type":"context",...}`. REPL prints one line only for the warning, in the
REPL's existing language, e.g. "Context 82 % of 200k (model X). If this work matters, switch to a model with a
larger context: /model". One-shot `--json` puts the last context dict in its output.

**Tests.** Fake loop/messages: overhead included; warning once at 80 %, not again at 85 %, again after a forced
compaction; `warn_percent` from config; bridge emits `context` after `final` and after `model_ok`; model switch
220k→1M clears the warning without compaction, 1M→220k at 91 % compacts on the next request; window priority
chain (config > endpoint fake > table > name > 32k default); compact ratio 0 / missing → 0.9.

## 1. Permissions and hooks

**Now (verified).**
- The loop does not enforce any policy. `_execute_tool_calls` (`loop.py:404-496`) parses args, adds `_role`
  and `_agent_id` (`:437-438`), fires `PRE_TOOL` (`:441-443`) and calls `tool.execute(**args)` (`:449`). No
  `PermissionPolicy` is consulted.
- `PermissionCheckingExecutor` (`permissions/executor.py:293-359`) is used only by the library facade
  `runtimelib/rex.py:94-99`, not by the CLI, REPL, JSONL bridge or ACP. Its ASK path raises
  `PermissionAskError` (`executor.py:351-356`); nothing catches it.
- `DefaultPermissionPolicy` (`permissions/policy.py:16-183`) is a hard-coded role table (CODER, TESTER, ...)
  with default deny; roles belong to the orchestrator, not to users. Not configurable from files.
- Hooks: `hooks/__init__.py` is an in-process Python registry (`HookRegistry`, `:83-113`), empty by default;
  return values of `trigger()` are ignored by the loop (`loop.py:441`, `:470`). No user-configured commands,
  no deny path.
- ACP says "no tool permission gating" (`acp/server.py:25-28`). Local mode (`--local-tools`,
  `runtime/__main__.py:46`, `:79`) runs every write and bash command with no question.

**Target.** Static rules allow/deny/ask per tool, per bash command pattern and per path; user-configured pre-
and post-tool hook commands; a pre-tool hook can deny. Mode sets defaults:

| Mode | read-only tools | write / bash / git write | network (webfetch) | MCP tools |
|---|---|---|---|---|
| Docker guard (default) | allow | `permissions.defaults.guard`, default **allow** | ask | ask |
| sandbox (configured OS sandbox, future) | allow | `permissions.defaults.sandbox`, default ask | ask | ask |
| local (`--local-tools`) | allow | **ask, fixed** (only an allow rule skips it) | ask | ask |

Deny rules always win, in every mode. One-shot mode without a UI (`rex "prompt"` with stdin not a TTY, or
`--json`) turns every remaining "ask" into deny; with a TTY the REPL asks on the terminal.

**Config (user config only, `~/.config/runtime/config.yaml` or `--config`; never from the repository).**

```yaml
permissions:
  defaults: {guard: allow, sandbox: ask}     # local is always ask
  allow: ["bash(pytest *)", "bash(git status*)", "fileops(read:**)", "edit(src/**)", "webfetch(domain:docs.python.org)"]
  ask:   ["bash(git push*)"]
  deny:  ["bash(rm -rf *)", "edit(**/.env)", "fileops(write:**/.env)", "mcp__github__delete_*"]
hooks:
  pre_tool:  [{match: "bash|edit", command: ["python", "/home/me/hooks/check.py"], timeout: 10}]
  post_tool: [{match: "edit", command: ["ruff", "format", "--stdin-filename", "x"], timeout: 20}]
  on_error: deny                              # pre_tool hook crash/timeout: deny (default) or ignore
```

Rule grammar `Tool(spec)`; `Tool` is a tool name or fnmatch glob. Spec per tool: bash = command glob;
fileops = `op:path-glob`; edit = path glob; git = `op *`; webfetch = `domain:host` (suffix match); MCP = no spec.
Bash DENY splits commands on `&&`, `||`, `;`, `|`, newline (best effort); any part that hits deny denies.
Bash ALLOW (superseded 2026-11-23): whitelist - only a single simple command of safe characters (letters, digits, space,
`- _ . / , : = + @`, plain quotes around whole words) can be auto-allowed; everything else asks. On Windows rex needs Git Bash. Paths are normalised
relative to the workspace before matching. Precedence: deny > ask > allow > mode default.
"allow_always" adds an exact rule for the rest of the process and persists it to
`~/.config/runtime/permissions/<sha1-of-workspace>.yaml` (user dir, per workspace, loaded as allow rules).

**Hook contract.** Command list (no shell), JSON on stdin:
`{"event":"pre_tool","tool":..,"args":{..},"cwd":..,"session":..,"mode":..}` (post_tool adds
`"ok","error","result_preview"`). Pre-tool: exit 0 = no opinion, or stdout JSON
`{"decision":"allow|deny|ask","reason":".."}`; exit 2 = deny, stderr is the reason; other exit/timeout =
`on_error`. A hook "allow" skips an ask but never overrides a deny rule. Post-tool: stdout text (max 2 KB) is
appended to the tool result as `hook_note`; it cannot undo the call. Hooks run with the workspace as cwd.

**Data flow per tool call** (new `agent/gate.py`, called from `_execute_tool_calls` before `execute`):
1. classify (tool kind: read/write/exec/network/mcp) and build the match string;
2. rules → deny ⇒ result error "Permission denied (rule X)";
3. pre_tool hooks → deny ⇒ error with reason; allow ⇒ skip 4;
4. if decision is ask ⇒ `asker.ask(PermissionRequest)` → allow_once/allow_always/deny; stop while waiting =
   deny + interrupt;
5. execute; 6. post_tool hooks; 7. the existing in-process `HookEngine` events stay as they are.
`summary` = one line ("bash: pytest -q", "edit src/a.py"); `detail` = full command, or the diff preview for
edits (tools may implement optional `describe(args) -> (summary, detail)`, default in `tools/base.py`).

**Askers.** `TerminalAsker` (REPL: prints summary/detail, reads `y`/`a`/`n`), `DenyAsker` (one-shot, no UI),
`JsonlAsker` (bridge: emits `permission`, blocks on a `threading.Event` that the reader thread sets when
`permission_reply` with the same id arrives; the reader must route replies directly, like `stop` today at
`cli/jsonl_bridge.py:129-135`, because the main thread is blocked in `loop.run()`). ACP maps it to
`session/request_permission`; today an incoming response (id, no method) is answered with "method not found"
(`acp/server.py:492-512`), so response routing is needed there.

**Tests.** Rule parsing/precedence table tests; compound bash splitting; path normalisation (`..`, absolute,
Windows separators); hook runner with tiny Python hook scripts (exit 0/2/1, JSON decision, timeout); gate with
fake tools and fake asker for each mode; bridge round trip with a scripted stdin (permission → reply);
one-shot deny; stop while waiting.

## 2. Edit tool with read-before-edit and unified diff

**Now.** `fileops` has `edit` (`tools/fileops.py:31`, `:99-105`, `:152-164`). Local mode replaces the first
occurrence even when `old_str` occurs many times (`:159-161`); the guard refuses that (`guard/entrypoint.py:
180-181`) — the two paths disagree. No read-before-edit check, no diff, result is only `{"ok":true}`; the UI
gets `tool_end` with `ok/error` only (`jsonl_bridge.py:89-94`).

**Target.** A dedicated `edit` tool: `path`, `old_string`, `new_string`, `replace_all=false`.
Exact match; zero matches = error with a hint; more than one without `replace_all` = error with the count; the
file must have been read (via `fileops read`) in this session and not changed since (sha256 at read time);
`old_string == new_string` = error; CRLF preserved; new file creation stays with `fileops write`. Returns
`{"ok","path","replacements","diff"}` with a `difflib.unified_diff` (3 lines context, capped at 400 lines,
"... N more lines" after). The diff is (a) the permission `detail` when asking, (b) shown after the call.
`fileops edit` stays for compatibility but routes to the same code (one behaviour). Guard mode: read via
`fs_read`, compute locally, check hash again, write via `fs_write` (no guard image change needed).

**Display.** `tool_end` gets an optional `"diff"` field (old UIs ignore it). REPL renderer prints it
coloured (`cli/render.py`), truncated unless `--verbose`.

**Tests.** unique/multiple/missing match; replace_all; not-read and changed-since-read refusals; CRLF file;
diff text exact for a small fixture; guard path with a fake guard client; fileops edit routes identically.

## 3. MCP client (stdio first)

**Now.** `runtimelib/mcp/__init__.py` (311 lines) is exported (`runtimelib/__init__.py:51`) but never used by
the loop. Problems: no `notifications/initialized` after `initialize` (`:176-191`); `stderr=PIPE` never read
(`:80`) → a chatty server blocks; `env=env or None` (`:83`) replaces the whole environment (no PATH); command
not resolved via `shutil.which` (Windows `npx.cmd`); server-initiated requests (ping, roots/list) ignored, so
servers may hang; no `nextCursor` paging in `tools/list` (`:193-204`); `isError` results not mapped; reader
thread exits silently when the process dies, then every call waits the full timeout; SSE/WebSocket stubs.

**Verdict: keep the dataclasses and the `MCPClient`/`MCPClientManager` API shape, rewrite the transport**
(about 200 lines): reader thread routes responses by id, answers server requests (`ping` → `{}`, others →
error -32601), drains stderr to a ring buffer (last 50 lines, shown on failure), merges `env` over
`os.environ`, fails pending calls immediately on EOF, sends `notifications/initialized`, pages `tools/list`,
drops non-stdio transports (`NotImplementedError`). Resources/prompts stay but are not wired.

**Wiring.** Config `mcp.servers.<name>: {command: [..], env: {..}, enabled: true, timeout: 60}`. At loop start
each enabled server is started (5 s init timeout; failure = one stderr line, server skipped). Each MCP tool
becomes `McpTool` (`tools/mcp_tool.py`) named `mcp__<server>__<tool>` (sanitised to `[A-Za-z0-9_-]`, ≤64
chars), schema from `inputSchema`, args stripped of `_role/_agent_id`, result = joined text content,
`isError` → failure. Kind = mcp (ask unless allowed). Note: in Docker mode MCP servers run on the host,
outside the guard — that is why they default to ask. Shutdown via `atexit` and `reset_context` keeps them.

**Tests.** A fixture stdio server in `tests/fixtures/mcp_echo_server.py` (stdlib, echo + error + slow tool +
stderr spam + one server-initiated ping); init handshake order; paging; timeout; process death; adapter naming
and result mapping; loop sees the tool in `tool_schemas`.

## 4. Sessions: save / resume / continue

**Now.** `SessionManager` (`session/__init__.py:50-137`) appends everything from every run to one global file
`~/.config/runtime/history.jsonl` (`:148`) and reads the whole file at start (`:64-72`). The loop writes types
`user_message`, `assistant_message`, `tool_call` (`loop.py:252`, `:280`, `:478-485`), but `get_messages()`
reconstructs only `user/assistant/tool/system` (`:96-102`) — so nothing can be rebuilt. Assistant messages
with `tool_calls` and `tool_call_id`s are not stored. `ChatMessage` has `to_dict` but no `from_dict`
(`llm/messages.py:26-32`). `/session` prints "not implemented" (`runtime/__main__.py:391-395`); ACP advertises
`loadSession: false` (`acp/server.py:304`). `session.max_history` is unused.

**Target.** One file per session: `~/.config/runtime/sessions/<id>.jsonl` (`session.dir`). First line
`{"type":"meta","id","cwd","model","started"}`; then one `{"type":"message","m":ChatMessage.to_dict()}` per
message appended to `state.messages` (exact replay, including tool calls/results); `{"type":"compact",
"messages":[...]}` after a compaction (resume starts from the last snapshot); `{"type":"title"}` = first user
line. Resume = load messages, `ensure_tool_results`, keep appending to the same file.
CLI: `--continue/-c` (latest session whose `cwd` equals the current one), `--resume <id>`, `rex sessions`
(list: id, updated, title, messages). REPL: `/session list|resume <id>|new`. JSONL: see table. `--jsonl
--continue/--resume` work too. The old global history.jsonl is no longer written (left on disk untouched).

**Tests.** Round trip of a conversation with tool calls → identical `messages`; resume after compaction;
`--continue` picks the right cwd; corrupt last line tolerated; list order; bridge `session` commands.

## 5. Web fetch tool

**Now.** Only `websearch`, a placeholder returning a fake result (`tools/websearch.py:44-51`). The guard has
`net.fetch` (`guard/entrypoint.py:244-260`) but the container runs with `network_mode: none` by default
(`guard/__init__.py:62`) and domain policy denies all when unset (`entrypoint.py:114-122`).

**Target.** `webfetch(url, max_chars=20000)`: http/https only; GET; 20 s timeout; 2 MB download cap; follow
≤5 redirects, re-checking each hop; refuse private/loopback/link-local addresses after DNS resolution unless
`webfetch.allow_private: true`; HTML → text with `html.parser` (drop script/style, keep headings, links as
`text (url)`); JSON/text returned as is; result `{"url","status","content_type","text","truncated"}`.
Runs in the rex host process in every mode (the host already has network for the LLM; the tool touches no
workspace files), via `kikolib.http_client`. Gated as kind network (ask unless `webfetch(domain:..)` allowed).
`websearch` is removed from the default tools until it is real (a fake result misleads the model).

**Tests.** Local `http.server` fixture on 127.0.0.1 with `allow_private` on: HTML→text, size cap, redirect
loop, non-http scheme, private-address refusal with it off, content types.

## JSONL protocol additions (all backwards compatible)

| Direction | Message | Fields | Notes |
|---|---|---|---|
| rex → UI | `permission` | `id`, `tool`, `kind`, `summary`, `detail` | One pending at a time; rex blocks until reply or `stop` |
| UI → rex | `permission_reply` | `id`, `decision`: `allow_once`/`allow_always`/`deny` | Unknown id → `error`; `stop` while pending = deny |
| rex → UI | `tool_end` (+field) | `diff` (optional string) | Present for edit; old UIs ignore it |
| rex → UI | `context` | `used`, `limit`, `percent`, `model`, `source`, `warning` (only when true) | After each `final` and after `model_ok`; warning once per arm |
| UI → rex | `session` | `action`: `list`/`resume`/`new`, `id` (resume) | Not while a chat runs (→ `error`) |
| rex → UI | `sessions` | `items`: [{`id`,`updated`,`title`,`messages`}] | Answer to `list` |
| rex → UI | `session_ok` | `id`, `messages` | Answer to `resume`/`new` |
| rex → UI | `ready` (+fields) | `session`, `mode` (`guard`/`sandbox`/`local`) | Existing event, new fields |
