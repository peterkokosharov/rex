## Executive Summary

**ai-rex is the most serious "agent runtime" codebase I've seen in open source.** Clean modular architecture (`runtimelib/` = reusable core, `runtime/` = thin wrapper), production-grade Docker Guard with real security boundaries, role-based permissions with fnmatch, git worktree isolation, MCP client, ACP/JSONL bridges, and a brilliant Claude CLI gateway.

**But:** "Everything is done" in README ≠ "everything works end-to-end." Critical pieces are stubs (TaskSpawnTool, websearch), Docker Guard network policy is TODO, pytest not installed, and the Orchestrator pipeline (P6) is planned but not built.

**Architectural finding:** ~20% of ai-rex is **orchestration logic** (TaskSpawnTool, role configs, tool choice policy) that belongs in an **external orchestrator layer**, not in the runtime. The runtime should be "small & clean" — tools, isolation, protocol only.

**Verdict:** Solid foundation. Focus on P0 integration before adding features. Extract orchestration to separate layer.

## 🏗️ Architectural Finding: Runtime vs Orchestration

**~20% of ai-rex is orchestration logic that belongs in an external orchestrator layer.**

| What's in ai-rex | Belongs in Runtime? | Should move to Orchestrator |
|------------------|---------------------|----------------------------|
| AgentLoop (minimal ReAct) | ✅ Yes | — |
| ToolExecutor (bash, fs, git, net) | ✅ Yes | — |
| Docker Guard / SandboxManager | ✅ Yes | — |
| PermissionGate | ✅ Yes | — |
| SessionManager + Checkpoints | ✅ Yes | — |
| HookEngine | ✅ Yes | — |
| **TaskSpawnTool** | ❌ No | ✅ **Move to Orchestrator** |
| **Role configs (ORCHESTRATOR, CODER...)** | ❌ No | ✅ **Policy file (policy.yaml)** |
| **Tool choice = always enabled** | ❌ No | ✅ **Heuristic / policy** |
| **max_steps = 60 hardcoded** | ❌ No | ✅ **Configurable / policy** |

**Recommendation:** Split into two layers:

```
┌─────────────────────────────────────────────────────────────┐
│                    ORCHESTRATOR (new package)               │
│  - Planning, task splitting, role assignment               │
│  - TaskSpawnTool (spawn_subagent RPC)                      │
│  - Role policies (policy.yaml)                             │
│  - Tool choice heuristic                                   │
│  - Review gates, git workflow, push decisions              │
├─────────────────────────────────────────────────────────────┤
│                    RUNTIME (runtimelib/)                    │
│  - AgentLoop (minimal ReAct: tool → result → continue)     │
│  - ToolExecutor (bash, fs, git, net, diagram)              │
│  - Sandbox (Docker Guard, worktrees, merge locks)          │
│  - Permissions (allow/deny/ask)                            │
│  - Session (JSONL, checkpoints)                            │
│  - Hooks (observability)                                   │
│  - Protocol (JSONL, ACP, MCP)                              │
└─────────────────────────────────────────────────────────────┘
```
